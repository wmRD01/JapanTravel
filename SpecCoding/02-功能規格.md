# 功能規格

## 1. 旅程管理功能

### 1.1 建立新旅程
**功能編號**: F-001

**功能描述**: 使用者可以建立新的旅遊旅程

**輸入**:
- 旅程標題（必填）
- 開始日期（必填）
- 天數（必填，1-30 天）

**處理流程**:
1. 使用者點擊「新增旅程」
2. 顯示設定 Modal
3. 使用者輸入標題、日期、天數
4. 點擊「開始規劃」
5. 系統生成唯一旅程 ID
6. 初始化預設資料結構
7. 儲存到 localStorage
8. 切換到新旅程

**輸出**:
- 新的旅程建立完成
- 自動切換到新旅程的編輯介面

**錯誤處理**:
- 標題為空：提示使用者輸入標題
- 日期無效：提示使用者選擇有效日期
- 天數超出範圍：限制在 1-30 天

---

### 1.2 切換旅程
**功能編號**: F-002

**功能描述**: 使用者可以在多個旅程之間切換

**輸入**:
- 旅程 ID

**處理流程**:
1. 使用者點擊側邊欄的旅程項目
2. 從 localStorage 載入旅程資料
3. 如果是雲端旅程，執行雲端同步
4. 更新當前旅程狀態
5. 顯示旅程資料

**輸出**:
- 切換到選定的旅程
- 顯示該旅程的所有資料

**特殊處理**:
- 雲端旅程：自動從 Firebase 同步最新資料
- 本地旅程：直接載入 localStorage 資料

---

### 1.3 刪除旅程
**功能編號**: F-003

**功能描述**: 使用者可以刪除不需要的旅程

**輸入**:
- 旅程 ID

**處理流程**:
1. 使用者點擊刪除按鈕
2. 顯示確認對話框
3. 確認後刪除 localStorage 資料
4. 如果是雲端旅程，提示是否同時刪除雲端資料
5. 更新旅程列表

**輸出**:
- 旅程已刪除
- 自動切換到其他旅程（如果有的話）

---

### 1.4 載入模板
**功能編號**: F-004

**功能描述**: 使用者可以載入預設的日本行程模板

**輸入**:
- 無（使用預設模板）

**處理流程**:
1. 使用者點擊「載入模板」
2. 顯示模板預覽
3. 確認後建立新旅程
4. 載入預設行程資料
5. 儲存到 localStorage

**輸出**:
- 新旅程建立完成，包含預設行程資料

---

## 3. 支出分帳功能

### 3.1 新增支出
**功能編號**: F-201

**功能描述**: 使用者可以新增支出記錄

**輸入**:
- 項目名稱（必填）
- 金額（必填）
- 付款人（多人模式必填）
- 時間（選填）
- 分攤對象（多人模式，可選）

**處理流程**:
1. 使用者輸入支出資訊
2. 選擇分攤對象（如果未選擇，預設為全體成員）
3. 點擊「新增」
4. 生成唯一的 order（用於雲端同步）
5. 新增到 expenses 陣列
6. 自動儲存到 localStorage
7. 如果是雲端旅程：
   - 立即上傳單筆到 Firestore
   - 排程背景自動同步（1 秒防抖）

**輸出**:
- 支出記錄已新增
- 自動計算分帳金額

**特殊處理**:
- 個人模式：付款人固定為「個人」，不分攤
- 多人模式：可選擇分攤對象，未選擇則全體分攤

---

### 3.2 刪除支出
**功能編號**: F-202

**功能描述**: 使用者可以刪除支出記錄

**輸入**:
- 支出索引

**處理流程**:
1. 使用者點擊刪除按鈕
2. 從 expenses 陣列中移除
3. 自動儲存到 localStorage
4. 如果是雲端旅程：
   - 從 Firestore 刪除該筆記錄

**輸出**:
- 支出記錄已刪除
- 自動重新計算分帳

---

### 3.3 計算分帳
**功能編號**: F-203

**功能描述**: 系統自動計算每人應付/應收金額

**計算邏輯**:
1. 計算每人實際支付金額（paidByPerson）
2. 計算每人應分攤金額（owedByPerson）
3. 計算差額（實際支付 - 應分攤）
4. 生成結算方案（誰該付給誰多少錢）

**輸出**:
- 每人已付金額
- 每人應付金額
- 結算方案

---

### 3.4 切換記帳模式
**功能編號**: F-204

**功能描述**: 使用者可以在個人記帳與多人分帳模式之間切換

**處理流程**:
1. 使用者點擊模式切換按鈕
2. 切換 isPersonalMode 狀態
3. 更新顯示的支出列表
4. 個人模式：顯示 personalExpenses
5. 多人模式：顯示 expenses

**輸出**:
- 記帳模式已切換
- 介面更新為對應模式

---

### 3.5 管理分帳成員
**功能編號**: F-205

**功能描述**: 使用者可以新增、刪除分帳成員

**輸入**:
- 成員名稱（逗號分隔）

**處理流程**:
1. 使用者編輯成員列表
2. 解析逗號分隔的字串
3. 更新 participants 陣列
4. 自動儲存到 localStorage
5. 重新計算分帳

**輸出**:
- 成員列表已更新
- 分帳金額重新計算

## 4. 雲端同步功能

### 4.1 上傳到雲端
**功能編號**: F-301

**功能描述**: 使用者可以將旅程資料上傳到 Firebase

**輸入**:
- 旅程資料（days, expenses, setup 等）

**處理流程**:
1. 使用者點擊「上傳到雲端」
2. 檢查 Firebase 連線狀態
3. 如果是第一次上傳：
   - 建立新的 trip 文件
   - 生成邀請碼
4. 如果是更新上傳：
   - 更新現有的 trip 文件
   - 刪除舊的 days 和 sharedExpenses
5. 上傳新的 days 資料
6. 上傳新的 sharedExpenses 資料
7. 儲存雲端資訊到 localStorage
8. 設定即時監聽器

**輸出**:
- 上傳成功提示
- 邀請碼（第一次上傳）
- 即時監聽器已啟動

**錯誤處理**:
- Firebase 連線失敗：提示使用者檢查網路
- 上傳失敗：顯示錯誤訊息

---

### 4.2 從雲端同步
**功能編號**: F-302

**功能描述**: 使用者可以從 Firebase 同步旅程資料

**輸入**:
- cloudTripId

**處理流程**:
1. 使用者點擊「從雲端同步」
2. 從 Firestore 讀取 trip 主文件
3. 讀取 days 子集合
4. 讀取 sharedExpenses 子集合
5. 更新本地資料（覆蓋模式）
6. 更新匯率、貨幣、語言等設定
7. 儲存到 localStorage

**輸出**:
- 同步成功提示
- 本地資料已更新為雲端最新版本

**特殊處理**:
- 匯率同步：優先使用雲端匯率，不會被本地舊值覆蓋
- 分帳成員同步：從雲端讀取並更新本地成員列表

---

### 4.3 即時監聽支出變更
**功能編號**: F-303

**功能描述**: 系統自動監聽 Firestore 的支出變更，實現多人即時協作

**處理流程**:
1. 設定 Firestore onSnapshot 監聽器
2. 監聽 `trips/{tripId}/sharedExpenses` 集合
3. 當有變更時：
   - 檢查是否為本地更新（isLocalUpdate 標記）
   - 如果是本地更新，忽略監聽器觸發
   - 如果是遠端更新，合併資料
4. 以 order 為唯一識別碼進行資料合併

**資料合併邏輯**:
- Firestore 有的、本地沒有的 → 新增
- 兩邊都有的 → 以 Firestore 為準更新
- Firestore 沒有的、本地有的 → 從本地刪除

**輸出**:
- 支出列表自動更新
- 分帳金額自動重新計算

---

### 4.4 生成邀請碼
**功能編號**: F-304

**功能描述**: 系統自動生成 6 位邀請碼

**處理流程**:
1. 使用隨機字元生成 6 位碼
2. 字元集：A-Z（排除 I、O）、2-9
3. 儲存到 Firestore trip 文件
4. 儲存到本地 localStorage

**輸出**:
- 6 位邀請碼

---

### 4.5 透過邀請碼載入旅程
**功能編號**: F-305

**功能描述**: 使用者可以透過邀請碼或邀請連結加入旅程

**輸入**:
- 邀請碼（URL 參數或手動輸入）

**處理流程**:
1. 檢查 URL 參數中的 code
2. 或使用者手動輸入邀請碼
3. 透過邀請碼查詢 Firestore
4. 檢查是否已存在本地旅程：
   - 已存在：更新雲端資訊並切換
   - 不存在：建立新本地旅程並連結
5. 執行雲端同步
6. 切換到該旅程

**輸出**:
- 旅程已載入
- 自動同步雲端資料

---
