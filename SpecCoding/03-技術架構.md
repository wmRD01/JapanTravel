# 技術架構

## 1. 架構概述

### 1.1 整體架構

GoJapan 採用**前後端分離**架構，前端使用 Vue 3 + TypeScript，後端使用 Firebase Firestore 作為雲端資料庫。

```
┌─────────────────────────────────────────┐
│           使用者瀏覽器                    │
│  ┌──────────────────────────────────┐   │
│  │      Vue 3 前端應用程式            │   │
│  │  ┌──────────┐  ┌──────────────┐ │   │
│  │  │ 本地儲存 │  │  Firebase    │ │   │
│  │  │(localStorage)│ (Firestore) │ │   │
│  │  └──────────┘  └──────────────┘ │   │
│  └──────────────────────────────────┘   │
└─────────────────────────────────────────┘
         │                    │
         │                    │
    ┌────▼────┐         ┌──────▼──────┐
    │ 本地資料 │         │  雲端資料庫   │
    │(優先使用)│         │  (Firestore) │
    └─────────┘         └──────────────┘
```

### 1.2 設計原則

-   **本地優先**: 所有資料優先儲存在本地，確保離線可用
-   **雲端同步**: 可選的雲端同步功能，支援多人協作
-   **模組化設計**: 使用 Composables 將功能模組化
-   **型別安全**: 完整的 TypeScript 型別定義

### 3.2 分層架構

#### 3.2.1 展示層（Components）

-   **職責**: UI 展示與使用者互動
-   **技術**: Vue 3 元件
-   **特點**:
    -   使用 `<script setup>` 語法
    -   Props/Emits 型別定義
    -   響應式設計

#### 3.2.2 業務邏輯層（Composables）

-   **職責**: 業務邏輯處理
-   **技術**: Vue 3 Composables
-   **特點**:
    -   可複用的邏輯封裝
    -   狀態管理
    -   副作用處理

#### 3.2.3 服務層（Services）

-   **職責**: 外部服務整合
-   **技術**: TypeScript 模組
-   **特點**:
    -   Firebase 操作
    -   API 呼叫
    -   資料轉換

#### 3.2.4 工具層（Utils）

-   **職責**: 通用工具函數
-   **技術**: TypeScript 函數
-   **特點**:
    -   純函數
    -   無副作用
    -   可測試

## 5. 資料流設計

### 5.1 本地資料流

```
使用者操作
    ↓
Composable 處理
    ↓
更新 Vue 狀態
    ↓
watch 監聽
    ↓
自動儲存到 localStorage
```

### 5.2 雲端資料流（上傳）

```
使用者操作
    ↓
Composable 處理
    ↓
更新本地狀態
    ↓
Service 層上傳到 Firestore
    ↓
儲存雲端資訊到 localStorage
```

### 5.3 雲端資料流（同步）

```
使用者觸發同步
    ↓
Service 層從 Firestore 讀取
    ↓
Composable 處理資料
    ↓
更新本地狀態（覆蓋模式）
    ↓
儲存到 localStorage
```

### 5.4 即時監聽資料流

```
Firestore 變更
    ↓
onSnapshot 觸發
    ↓
檢查 isLocalUpdate 標記
    ↓
資料合併（以 order 為依據）
    ↓
更新本地狀態
    ↓
儲存到 localStorage
```

## 6. 狀態管理設計

### 6.1 狀態結構

```typescript
{
  // 旅程相關
  currentTripId: string | null
  cloudTripId: string | null
  tripList: TripMeta[]

  // UI 狀態
  viewMode: 'plan' | 'map' | 'money' | 'translate'
  showSetupModal: boolean
  // ...
}
```

### 6.2 狀態管理方式

-   **響應式狀態**: 使用 Vue 3 `ref` 和 `reactive`
-   **計算屬性**: 使用 `computed` 處理衍生狀態
-   **本地持久化**: 使用 `watch` 自動儲存到 localStorage
-   **雲端同步**: 手動觸發或自動排程

## 7. 資料同步策略

### 7.1 本地優先策略

-   所有操作先更新本地狀態
-   本地儲存優先於雲端同步
-   離線環境下仍可使用

### 7.2 雲端同步策略

-   **上傳**: 覆蓋模式，刪除舊資料後上傳新資料
-   **同步**: 單向拉取，Firebase → 本地，覆蓋本地資料
-   **即時監聽**: 僅監聽支出資料，其他資料需手動同步

### 7.3 衝突解決策略

-   **支出資料**: 以 `order` 為唯一識別碼，Firestore 優先
-   **其他資料**: 同步時以 Firestore 為準（覆蓋模式）
-   **匯率**: 初始化時優先使用雲端匯率

## 8. 錯誤處理設計

### 8.1 錯誤類型

-   **網路錯誤**: Firebase 連線失敗、API 呼叫失敗
-   **資料錯誤**: 資料格式錯誤、缺少必要欄位
-   **使用者錯誤**: 輸入驗證失敗

### 8.2 錯誤處理策略

-   **網路錯誤**: 顯示錯誤提示，保留本地資料
-   **資料錯誤**: 使用預設值或提示使用者
-   **使用者錯誤**: 即時驗證，顯示錯誤訊息

### 8.3 降級方案

-   Firebase 連線失敗：使用本地資料
-   API 呼叫失敗：保留上次成功結果
-   地理編碼失敗：不顯示地圖標記

## 12. 技術決策記錄

### 12.1 為什麼選擇 Vue 3？

-   Composition API 提供更好的邏輯組織
-   TypeScript 支援完善
-   生態系統成熟

### 12.2 為什麼選擇 Firebase？

-   即時資料庫功能
-   無需後端開發
-   免費方案足夠使用

### 12.3 為什麼選擇 localStorage？

-   本地優先策略
-   離線可用
-   隱私保護

### 12.4 為什麼使用 Composables？

-   邏輯複用
-   易於測試
-   清晰的職責分離
