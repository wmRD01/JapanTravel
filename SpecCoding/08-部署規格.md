# 部署規格

## 1. 部署概述

### 1.1 部署目標
將 GoJapan 應用程式部署到生產環境，提供穩定的服務。

### 1.2 部署方式
- **前端**: 靜態檔案部署
- **後端**: Firebase Firestore（無需部署）
- **CDN**: 可選（加速載入）

---

## 2. 環境設定

### 2.1 開發環境
**用途**: 開發和測試

**設定**:
- Node.js 18+
- npm 或 yarn
- 現代瀏覽器

**指令**:
```bash
npm install
npm run dev
```

---

### 2.2 生產環境
**用途**: 正式服務

**設定**:
- 靜態檔案伺服器
- HTTPS 支援
- CDN（可選）

**建置指令**:
```bash
npm run build
```

**輸出目錄**: `dist/`

## 4. Firebase 設定

### 4.1 Firebase 專案設定
1. 在 Firebase Console 建立專案
2. 啟用 Firestore
3. 取得 Firebase 設定檔

### 4.2 Firebase 設定檔位置
**檔案**: `data/trip-data.ts`

**內容**:
```typescript
export const FIREBASE_CONFIG: FirebaseConfig = {
  apiKey: "...",
  authDomain: "...",
  projectId: "...",
  storageBucket: "...",
  messagingSenderId: "...",
  appId: "..."
};
```

### 4.3 Firestore 安全規則
**位置**: Firebase Console → Firestore → Rules

**規則範例**:
```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /trips/{tripId} {
      allow read, write: if true; // 測試用
      match /{document=**} {
        allow read, write: if true;
      }
    }
  }
}
```

**注意**: 生產環境需加強安全規則

### 5.3 Geoapify API

**設定位置**: `src/utils/geoapify.ts`

**取得方式**:
1. 註冊 Geoapify 帳號
2. 取得 API Key
3. 更新 `getApiKey()` 函數

**注意**: 目前 API Key 在前端，建議移至環境變數（未來改進）

## 6. 部署選項

### 6.1 靜態檔案伺服器

#### 選項 1: GitHub Pages
**步驟**:
1. 建置專案
2. 將 `dist/` 內容推送到 `gh-pages` 分支
3. 在 GitHub 設定中啟用 Pages

**優點**: 免費、簡單
**缺點**: 僅支援靜態檔案

---

#### 選項 2: Netlify
**步驟**:
1. 連接 GitHub 儲存庫
2. 設定建置指令: `npm run build`
3. 設定發布目錄: `dist`
4. 部署

**優點**: 自動部署、CDN、HTTPS
**缺點**: 免費方案有限制

---

#### 選項 3: Vercel
**步驟**:
1. 連接 GitHub 儲存庫
2. 設定建置指令: `npm run build`
3. 設定輸出目錄: `dist`
4. 部署

**優點**: 自動部署、CDN、HTTPS
**缺點**: 免費方案有限制

---

#### 選項 4: Firebase Hosting
**步驟**:
1. 安裝 Firebase CLI
   ```bash
   npm install -g firebase-tools
   ```

2. 初始化 Firebase
   ```bash
   firebase init hosting
   ```

3. 設定 `public` 目錄為 `dist`

4. 建置並部署
   ```bash
   npm run build
   firebase deploy --only hosting
   ```

**優點**: 與 Firebase 整合、CDN、HTTPS
**缺點**: 需 Firebase 帳號

---

### 6.2 自架伺服器

#### 使用 Nginx
**設定範例**:
```nginx
server {
    listen 80;
    server_name your-domain.com;
    
    root /path/to/dist;
    index index.html;
    
    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

## 12. 安全性考量

### 12.1 HTTPS
- **必須**: 生產環境必須使用 HTTPS
- **原因**: 保護資料傳輸、支援 Geolocation API

### 12.2 Firebase 安全規則
- **測試環境**: 開放讀寫（僅測試用）
- **生產環境**: 需加強安全規則

### 12.3 API Key 保護
- **目前**: API Key 在前端（不理想）
- **未來**: 移至後端或環境變數

## 15. 故障排除

### 15.1 常見問題

#### 問題 1: Firebase 連線失敗
**原因**: 
- 網路問題
- Firebase 設定錯誤
- 安全規則限制

**解決**:
- 檢查網路連線
- 檢查 Firebase 設定
- 檢查安全規則

---

#### 問題 2: 外部 API 呼叫失敗
**原因**:
- API 服務中斷
- API Key 錯誤
- 網路問題

**解決**:
- 檢查 API 服務狀態
- 檢查 API Key
- 檢查網路連線

---

#### 問題 3: 地圖無法顯示
**原因**:
- Leaflet 載入失敗
- 網路問題

**解決**:
- 檢查網路連線
- 檢查 Leaflet CDN
