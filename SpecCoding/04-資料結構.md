# 資料結構

## 1. 本地儲存結構（localStorage）

### 1.1 儲存鍵值格式

```
{tripId}_{suffix}
```

**範例**:

-   `trip_123_days` - 行程資料
-   `trip_123_exp` - 支出資料
-   `trip_123_config` - 設定資料
-   `trip_123_cloud` - 雲端資訊
-   `trip_123_rate` - 匯率
-   `trip_123_users` - 分帳成員

### 1.2 旅程列表

**鍵值**: `tripList`
**格式**: JSON 字串

```typescript
TripMeta[] = [
  {
    id: string;
    destination: string;
    startDate: string;
    daysCount: number;
    isCloudTrip?: boolean;
  }
]
```

## 2. 核心資料型別

### 2.1 Day（行程天數）

```typescript
interface Day {
    date: string; // 日期顯示字串，如 "02/17"
    shortDate: string; // 簡短日期，如 "02/17"
    fullDate: string; // 完整日期，如 "2025-02-17"
    title: string; // 標題，如 "抵達日本・成田住宿"
    items: DayItem[]; // 行程項目陣列
    flight: Flight | null; // 航班資訊（可選）
    order?: number; // 排序順序（用於雲端同步）
    region?: string; // 該行程的地區設定（用於天氣查詢）
    weather?: DayWeather; // 該行程的天氣資料
}
```

### 2.2 DayItem（行程項目）

```typescript
interface DayItem {
    time: string; // 時間，如 "12:50"
    type: 'spot' | 'food' | 'shop' | 'transport' | 'flight' | 'country-divider';
    activity: string; // 活動名稱
    location: string; // 地點
    note: string; // 備註
    region?: string; // 該項目的地區設定
    weather?: DayWeather; // 該項目的天氣資料
    // 國家區塊專用欄位
    country?: string; // 國家名稱，如 "日本"
    countryCode?: string; // 國家代碼，如 "JP"
    isCountryDivider?: boolean; // 標記為國家區塊
}
```

### 2.3 Flight（航班資訊）

```typescript
interface Flight {
    type: 'arrival' | 'departure'; // 抵達或出發
    startTime: string; // 起飛時間
    startAirport: string; // 起飛機場代碼
    number: string; // 航班號碼
    endTime: string; // 抵達時間
    endAirport: string; // 抵達機場代碼
    arrivalOffset: number; // 時差（小時）
}
```

### 2.4 Expense（支出）

```typescript
interface Expense {
    item: string; // 項目名稱
    amount: number; // 金額
    payer: string; // 付款人
    order: string; // 唯一識別碼（用於雲端同步）
    splitParticipants: string[]; // 分攤對象陣列
    time?: string; // 時間（選填）
}
```

### 2.5 Setup（設定）

```typescript
interface Setup {
    title: string; // 旅程標題
    startDate: string; // 開始日期（ISO 格式）
    days: number; // 天數
    rate: number; // 匯率（會同步到雲端）
    currency: string; // 貨幣代碼，如 "JPY"
    langCode: string; // 語言代碼，如 "ja"
    langName: string; // 語言名稱，如 "日文"
}
```

### 2.6 TripMeta（旅程元資料）

```typescript
interface TripMeta {
    id: string; // 旅程 ID
    destination: string; // 目的地（顯示用）
    startDate: string; // 開始日期
    daysCount: number; // 天數
    isCloudTrip?: boolean; // 是否為雲端旅程
}
```

### 2.7 CloudData（雲端資訊）

```typescript
interface CloudData {
    cloudTripId: string | null; // Firebase trip 文件 ID
    inviteCode: string; // 邀請碼
    isCloudTrip: boolean; // 是否為雲端旅程
    lastSyncedAt?: string; // 最後同步時間（ISO 格式）
}
```

## 3. Firestore 資料結構

### 3.1 主文件結構

```
trips/{tripId}
```

**文件內容**:

```typescript
{
    title: string; // 旅程標題
    startDate: string; // 開始日期
    daysCount: number; // 天數
    inviteCode: string; // 邀請碼
    participants: string; // 分帳成員（逗號分隔字串）
    config: {
        currency: string; // 貨幣代碼
        rate: number; // 匯率
        langCode: string; // 語言代碼
        langName: string; // 語言名稱
    }
    createdAt: Timestamp; // 建立時間
    updatedAt: Timestamp; // 更新時間
}
```

### 3.2 子集合：days（行程天數）

```
trips/{tripId}/days/{dayId}
```

**文件內容**:

```typescript
{
  order: number;                    // 排序順序
  date: string;                      // 日期顯示字串
  shortDate: string;                 // 簡短日期
  fullDate: string;                  // 完整日期
  title: string;                     // 標題
  flight: Flight | null;            // 航班資訊
  region: string;                    // 地區
  items: DayItem[];                  // 行程項目（不包含 weather）
}
```

**注意**: items 中的 weather 欄位會被過濾，不上傳到 Firestore

### 3.3 子集合：sharedExpenses（共同支出）

```
trips/{tripId}/sharedExpenses/{order}
```

**文件內容**:

```typescript
{
  item: string;                     // 項目名稱
  amount: number;                    // 金額
  payerName: string;                 // 付款人（Firestore 使用 payerName）
  order: string;                     // 唯一識別碼（作為文件 ID）
  splitParticipants: string[];      // 分攤對象陣列
  createdAt: Timestamp;               // 建立時間
}
```

**注意**:

-   文件 ID 使用 `order` 值
-   使用 `payerName` 而非 `payer`（為了與本地 Expense 區分）

### 3.4 子集合：personalExpenses（個人記帳）

```
trips/{tripId}/personalExpenses/{order}
```

**文件內容**:

```typescript
{
    item: string; // 項目名稱
    amount: number; // 金額
    payerName: string; // 付款人（固定為 "個人"）
    order: string; // 唯一識別碼（作為文件 ID）
    createdAt: Timestamp; // 建立時間
}
```

## 4. 資料轉換規則

### 4.1 本地 → Firestore（上傳）

-   `Expense.payer` → `sharedExpenses.payerName`
-   `DayItem.weather` → 過濾（不上傳）
-   `Day.weather` → 過濾（不上傳）
-   `Expense.order` → 作為文件 ID

### 4.2 Firestore → 本地（同步）

-   `sharedExpenses.payerName` → `Expense.payer`
-   `sharedExpenses.splitParticipants` → 如果為空，使用預設成員
-   `config.rate` → `exchangeRate` 和 `setup.rate`
-   `participants`（字串）→ `participants`（陣列）

---

## 5. 資料驗證規則

### 5.1 Day 驗證

-   `date`, `shortDate`, `fullDate` 必須存在
-   `items` 必須是陣列
-   `flight` 可以是 null 或有效的 Flight 物件

### 5.2 DayItem 驗證

-   `type` 必須是有效的類型
-   `activity` 和 `location` 建議不為空
-   `isCountryDivider` 為 true 時，`country` 和 `countryCode` 應該存在

### 5.3 Expense 驗證

-   `item` 必須存在且不為空
-   `amount` 必須是數字且 >= 0
-   `payer` 必須存在
-   `order` 必須存在（用於雲端同步）
-   `splitParticipants` 必須是陣列

### 5.4 Setup 驗證

-   `title` 建議不為空
-   `startDate` 必須是有效的日期字串
-   `days` 必須是數字且 1 <= days <= 30
-   `rate` 必須是數字且 > 0
-   `currency` 必須是有效的貨幣代碼

## 6. 資料預設值

### 6.1 新建旅程預設值

```typescript
{
  title: '旅遊計畫',
  startDate: 今天日期,
  days: 1,
  rate: 0.215,              // 預設日圓匯率
  currency: 'JPY',
  langCode: 'ja',
  langName: '日文'
}
```

### 6.2 新建天數預設值

```typescript
{
  date: `Day ${days.length + 1}`,
  shortDate: '',
  fullDate: '',
  title: '',
  items: [],
  flight: null
}
```

### 6.3 新建項目預設值

```typescript
{
  time: '',
  type: 'spot',
  activity: '',
  location: '',
  note: ''
}
```

### 6.4 新建支出預設值

```typescript
{
  item: '',
  amount: 0,
  payer: '我',              // 多人模式預設
  order: `${Date.now()}_${payer}`,  // 自動生成
  splitParticipants: []     // 未選擇時使用全體成員
}
```

### 6.5 預設分帳成員

```typescript
['我', '旅伴A'];
```

## 7. 資料唯一識別碼

### 7.1 旅程 ID

-   **格式**: `trip_{timestamp}_{random}`
-   **生成方式**: `generateId()` 函數
-   **用途**: 本地儲存鍵值、旅程識別

### 7.2 支出 order

-   **格式**: `${Date.now()}_${payer}`
-   **生成方式**: 新增支出時自動生成
-   **用途**: 雲端同步唯一識別碼、Firestore 文件 ID

### 7.3 邀請碼

-   **格式**: 6 位隨機字元
-   **字元集**: A-Z（排除 I、O）、2-9
-   **生成方式**: `generateInviteCode()` 函數
-   **用途**: 分享旅程、查詢旅程

## 8. 資料同步標記

### 8.1 isLocalUpdate

-   **用途**: 標記是否為本地更新
-   **使用場景**: 避免本地更新時觸發即時監聽器的循環更新
-   **生命週期**:
    -   本地更新前設為 `true`
    -   更新完成後設為 `false`

### 8.2 expensesSyncInProgress

-   **用途**: 標記支出同步是否進行中
-   **使用場景**: 防止重複同步

### 8.3 expensesSyncAbortFlag

-   **用途**: 標記是否取消同步
-   **使用場景**: 背景自動同步時，如果使用者快速操作，取消舊的同步

## 9. 資料合併邏輯

### 9.1 支出資料合併（以 order 為依據）

```
本地資料: Map<order, Expense>
雲端資料: Map<order, Expense>

合併規則:
1. 雲端有的、本地沒有的 → 新增到本地
2. 兩邊都有的 → 以雲端為準更新本地
3. 雲端沒有的、本地有的 → 從本地刪除
```

### 9.2 其他資料合併

-   **同步模式**: 覆蓋模式（Firestore → 本地）
-   **上傳模式**: 覆蓋模式（本地 → Firestore，刪除舊資料後上傳）

---

## 10. 資料儲存優先順序

### 10.1 讀取優先順序

1. **雲端旅程 + 同步成功**: 使用雲端資料
2. **雲端旅程 + 同步失敗**: 使用本地資料
3. **本地旅程**: 使用本地資料

### 10.2 寫入優先順序

1. **立即**: 更新本地狀態
2. **自動**: 儲存到 localStorage
3. **背景**: 如果是雲端旅程，上傳到 Firestore

---

## 11. 資料清理規則

### 11.1 上傳時清理

-   刪除舊的 `days` 子集合
-   刪除舊的 `sharedExpenses` 子集合
-   保留主文件，更新內容

### 11.2 同步時清理

-   覆蓋本地資料（不保留舊資料）
-   更新 localStorage

### 11.3 刪除旅程時清理

-   刪除所有相關的 localStorage 資料
-   可選：刪除 Firestore 資料（需手動確認）
